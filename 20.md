SLIP-20
=======

WebID Profile
-------------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes |

This SLIP defines WebID profiles for Solid Lite identity.

## Overview

A WebID is a URI that identifies an agent (person, organization, or bot). When dereferenced, it returns a machine-readable profile document.

## Format

WebIDs use a URI with a fragment identifier:
```
https://alice.example.com/#me
https://example.com/alice/profile#me
```

## Profile Document

The profile is served as JSON-LD (or Turtle) at the WebID URI:

```json
{
  "@context": [
    "https://www.w3.org/ns/activitystreams",
    "https://w3id.org/webid"
  ],
  "@id": "#me",
  "type": "Person",
  "name": "Alice",
  "preferredUsername": "alice",
  "inbox": "./inbox/",
  "outbox": "./outbox/",
  "storage": "/",
  "knows": [
    "https://bob.example.com/#me"
  ]
}
```

## Required Properties

| Property | Description |
|----------|-------------|
| `@id` | Fragment identifier (#me) |
| `type` | Person, Organization, etc. |
| `name` | Display name |

## Recommended Properties

| Property | Description |
|----------|-------------|
| `preferredUsername` | Short username |
| `storage` | Root storage location |
| `inbox` | ActivityPub inbox |
| `outbox` | ActivityPub outbox |

## Discovery

Profiles SHOULD be at the root of storage:
```
https://alice.example.com/        → Profile
https://alice.example.com/#me     → WebID
```

## Linking to did:nostr

WebID profiles can link to Nostr identity:
```json
{
  "@id": "#me",
  "type": "Person",
  "name": "Alice",
  "sameAs": "did:nostr:f0af1228..."
}
```
