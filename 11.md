SLIP-11
=======

CORS Headers
------------

`draft` `mandatory` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes |

This SLIP defines the required CORS headers for cross-origin browser access.

## Overview

Solid applications integrate data from multiple origins. CORS headers allow browsers to make cross-origin requests to Solid Lite servers.

## Required Headers

Servers MUST include these headers in responses:

```http
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, HEAD, OPTIONS, PUT, DELETE, POST, PATCH
Access-Control-Allow-Headers: Accept, Authorization, Content-Type, If-Match, If-None-Match, Link, Slug
Access-Control-Expose-Headers: Accept-Patch, Accept-Post, ETag, Link, Location, WAC-Allow
Access-Control-Allow-Credentials: true
```

## Preflight Requests

Servers MUST respond to OPTIONS preflight requests with:
- Status: 200 OK or 204 No Content
- All CORS headers above
- `Access-Control-Max-Age: 86400` (optional, for caching)

## Example

Request:
```http
OPTIONS /resource HTTP/1.1
Host: example.com
Origin: https://app.example.org
Access-Control-Request-Method: PUT
```

Response:
```http
HTTP/1.1 204 No Content
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, HEAD, OPTIONS, PUT, DELETE, POST, PATCH
Access-Control-Allow-Headers: Accept, Authorization, Content-Type
Access-Control-Max-Age: 86400
```
