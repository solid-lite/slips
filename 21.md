SLIP-21
=======

did:nostr Identity
------------------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes (v0.0.22+) |

This SLIP defines using `did:nostr` as an identity method in Solid Lite, enabling decentralized identity based on Nostr public keys.

## Overview

A `did:nostr` identifier is a Decentralized Identifier (DID) derived from a Nostr public key. It provides self-sovereign identity without registration, passwords, or central authorities.

## Format

```
did:nostr:<64-character-lowercase-hex-pubkey>
```

Example:
```
did:nostr:f0af1228a863772c0661ca0dd2586c58668de52ca9f71973404e7b9b1f5edc4d
```

## Properties

| Property | Description |
|----------|-------------|
| **Self-certifying** | The public key proves ownership |
| **No registration** | Any Nostr keypair works immediately |
| **Offline-first** | Identity can be verified without network |
| **Interoperable** | Works with Nostr ecosystem |

## Resolution

A `did:nostr` can be resolved to a DID Document. Per the [did:nostr spec](https://nostrcg.github.io/did-nostr/), resolution supports:

1. **Offline resolution** — Generate DID Document from pubkey alone
2. **HTTP resolution** — Fetch from `/.well-known/did/nostr/<pubkey>.json`
3. **Enhanced resolution** — Query Nostr relays for profile metadata

### Minimal DID Document

```json
{
  "@context": ["https://www.w3.org/ns/did/v1"],
  "id": "did:nostr:f0af1228...",
  "verificationMethod": [{
    "id": "did:nostr:f0af1228...#key-0",
    "type": "SchnorrSecp256k1VerificationKey2019",
    "controller": "did:nostr:f0af1228...",
    "publicKeyHex": "f0af1228..."
  }],
  "authentication": ["did:nostr:f0af1228...#key-0"]
}
```

## Use in ACLs

`did:nostr` identities can be used in Web Access Control (WAC) ACL files:

```turtle
@prefix acl: <http://www.w3.org/ns/auth/acl#>.

<#authorization>
    a acl:Authorization;
    acl:agent <did:nostr:f0af1228a863772c0661ca0dd2586c58668de52ca9f71973404e7b9b1f5edc4d>;
    acl:accessTo </resource>;
    acl:mode acl:Read, acl:Write.
```

## Relationship to WebID

`did:nostr` can complement or replace WebID:

| Approach | Description |
|----------|-------------|
| **did:nostr only** | Use Nostr key as sole identity |
| **WebID only** | Traditional Solid identity |
| **Linked** | Connect did:nostr to WebID via `owl:sameAs` |

### Linking Example

In a WebID profile:
```turtle
<#me> owl:sameAs <did:nostr:f0af1228...> .
```

## Authentication

Use [SLIP-82 (Schnorr Auth)](./82.md) to authenticate with a did:nostr identity.

## Benefits

- **No email required** — Identity from keypair
- **No password** — Authenticate with signatures
- **Portable** — Same identity across all servers
- **Privacy** — Create new identities freely
