SLIP-84
=======

Built-in Identity Provider
--------------------------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes |

This SLIP defines a built-in Solid-OIDC Identity Provider for self-hosted authentication.

## Overview

While SLIP-83 covers Solid-OIDC as a resource server, this SLIP covers running your own Identity Provider. This enables complete self-sovereignty — users authenticate directly with their data server.

## Discovery

The IDP is discovered via OpenID Connect Discovery:

```http
GET /.well-known/openid-configuration HTTP/1.1
Host: example.com
```

Response:

```json
{
  "issuer": "https://example.com",
  "authorization_endpoint": "https://example.com/.idp/auth",
  "token_endpoint": "https://example.com/.idp/token",
  "userinfo_endpoint": "https://example.com/.idp/userinfo",
  "jwks_uri": "https://example.com/.idp/jwks",
  "registration_endpoint": "https://example.com/.idp/register",
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "token_endpoint_auth_methods_supported": ["none"],
  "dpop_signing_alg_values_supported": ["ES256"],
  "subject_types_supported": ["public"],
  "id_token_signing_alg_values_supported": ["ES256"]
}
```

## Authentication Flow

### 1. Authorization Request

```http
GET /.idp/auth?
  response_type=code&
  client_id=https://app.example/&
  redirect_uri=https://app.example/callback&
  scope=openid webid&
  state=xyz&
  code_challenge=ABC123&
  code_challenge_method=S256
```

### 2. User Login

The IDP presents a login form. User authenticates with:
- Username/password (SLIP-85)
- Or WebAuthn/passkeys (future)

### 3. Authorization Code

```http
HTTP/1.1 302 Found
Location: https://app.example/callback?code=AUTH_CODE&state=xyz
```

### 4. Token Exchange

```http
POST /.idp/token HTTP/1.1
Content-Type: application/x-www-form-urlencoded
DPoP: eyJ0eXAiOiJkcG9wK2p3dCIs...

grant_type=authorization_code&
code=AUTH_CODE&
redirect_uri=https://app.example/callback&
client_id=https://app.example/&
code_verifier=ORIGINAL_VERIFIER
```

Response:

```json
{
  "access_token": "eyJhbGciOiJFUzI1NiIs...",
  "token_type": "DPoP",
  "expires_in": 3600,
  "id_token": "eyJhbGciOiJFUzI1NiIs..."
}
```

## WebID in Tokens

The access token contains the user's WebID:

```json
{
  "webid": "https://example.com/alice/#me",
  "iss": "https://example.com",
  "sub": "user-uuid",
  "aud": "solid",
  "iat": 1704067200,
  "exp": 1704070800,
  "client_id": "https://app.example/"
}
```

## JWKS Endpoint

Public keys for token verification:

```http
GET /.idp/jwks HTTP/1.1
```

```json
{
  "keys": [{
    "kty": "EC",
    "crv": "P-256",
    "x": "...",
    "y": "...",
    "kid": "key-id",
    "use": "sig",
    "alg": "ES256"
  }]
}
```

## Client Registration

Dynamic client registration:

```http
POST /.idp/register HTTP/1.1
Content-Type: application/json

{
  "redirect_uris": ["https://app.example/callback"],
  "client_name": "My Solid App"
}
```

## Storage Layout

```
/.idp/
  ├── accounts/       # User accounts (SLIP-85)
  ├── clients/        # Registered clients
  ├── keys/           # Signing keys
  └── interaction/    # Session data
```

## Configuration

```javascript
{
  "idp": true,
  "idpIssuer": "https://example.com"
}
```
