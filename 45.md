SLIP-45
=======

Subdomain Mode
--------------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes |

This SLIP defines subdomain-based pod isolation for enhanced security.

## Overview

Subdomain mode gives each user their own subdomain (e.g., `alice.example.com`). This provides XSS protection through browser same-origin policy — JavaScript on one pod cannot access another pod's data.

## URL Mapping

| Path Mode | Subdomain Mode |
|-----------|----------------|
| `example.com/alice/` | `alice.example.com/` |
| `example.com/alice/profile` | `alice.example.com/profile` |
| `example.com/bob/` | `bob.example.com/` |

## Configuration

```javascript
{
  "subdomains": true,
  "baseDomain": "example.com"
}
```

Or via environment:

```bash
JSS_SUBDOMAINS=true
JSS_BASE_DOMAIN=example.com
```

## DNS Setup

Wildcard DNS record required:

```
*.example.com.  A      203.0.113.10
*.example.com.  AAAA   2001:db8::10
```

Or with CNAME:

```
*.example.com.  CNAME  example.com.
```

## SSL/TLS

Wildcard certificate required:

```
Common Name: *.example.com
Subject Alternative Names:
  - *.example.com
  - example.com
```

Let's Encrypt supports wildcard via DNS-01 challenge:

```bash
certbot certonly --manual --preferred-challenges dns \
  -d example.com -d *.example.com
```

## Security Benefits

### XSS Isolation

Without subdomains:
- Script on `/alice/app.js` can read `/bob/private/`
- Cookies shared across all pods

With subdomains:
- `alice.example.com` scripts cannot access `bob.example.com`
- Separate cookie jars per pod

### Same-Origin Policy

| Origin A | Origin B | Access |
|----------|----------|--------|
| `alice.example.com` | `alice.example.com` | ✅ Allowed |
| `alice.example.com` | `bob.example.com` | ❌ Blocked |
| `alice.example.com` | `example.com` | ❌ Blocked |

## WebID URLs

WebIDs adjust to use subdomains:

```
Path mode:      https://example.com/alice/#me
Subdomain mode: https://alice.example.com/#me
```

## Root Domain

The root domain (`example.com`) serves:
- Landing page / documentation
- Registration (`/.pods`)
- IDP endpoints (`/.idp/*`)
- Global `.well-known` paths

## Request Routing

```javascript
function getPodFromHost(host, baseDomain) {
  if (host === baseDomain) return null; // Root domain

  const subdomain = host.replace(`.${baseDomain}`, '');
  return subdomain; // Pod name
}
```

## CORS Considerations

In subdomain mode, cross-pod requests require CORS:

```http
GET /profile HTTP/1.1
Host: alice.example.com
Origin: https://bob.example.com

HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://bob.example.com
Access-Control-Allow-Credentials: true
```
