SLIP-85
=======

User Registration
-----------------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes |

This SLIP defines user registration and account management.

## Overview

User registration creates accounts with associated pods and WebID profiles. This SLIP covers both the API for programmatic account creation and the web-based registration flow.

## Registration API

### Create Account

```http
POST /.pods HTTP/1.1
Content-Type: application/json

{
  "name": "alice",
  "email": "alice@example.com",
  "password": "secure-password"
}
```

Response:

```json
{
  "webId": "https://example.com/alice/#me",
  "podUrl": "https://example.com/alice/",
  "username": "alice"
}
```

### Minimal Registration

Email is optional — username is sufficient:

```http
POST /.pods HTTP/1.1
Content-Type: application/json

{
  "name": "bob",
  "password": "secure-password"
}
```

## Account Storage

Accounts are stored with hashed passwords:

```json
{
  "id": "uuid-here",
  "username": "alice",
  "email": "alice@example.com",
  "passwordHash": "$2b$10$...",
  "webId": "https://example.com/alice/#me",
  "createdAt": "2024-01-01T00:00:00Z"
}
```

## WebID Profile Creation

Registration creates a WebID profile:

```turtle
@prefix foaf: <http://xmlns.com/foaf/0.1/>.
@prefix solid: <http://www.w3.org/ns/solid/terms#>.

<#me>
    a foaf:Person;
    foaf:name "alice";
    solid:oidcIssuer <https://example.com>;
    solid:account </alice/>.
```

## Pod Structure

New accounts get a pod with default structure:

```
/alice/
  ├── profile         # WebID profile (card)
  ├── .acl            # Root ACL
  ├── inbox/          # LDP inbox
  ├── settings/
  │   ├── prefs.ttl   # Preferences
  │   ├── privateTypeIndex.ttl
  │   └── publicTypeIndex.ttl
  └── public/         # Public files
```

## Web Registration Flow

### 1. Registration Form

```http
GET /.idp/register HTTP/1.1
Accept: text/html
```

Returns HTML registration form.

### 2. Form Submission

```http
POST /.idp/register HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=alice&email=alice%40example.com&password=secret&confirm=secret
```

### 3. Redirect to Pod

```http
HTTP/1.1 302 Found
Location: /alice/
```

## Credentials Endpoint (CTH)

For conformance testing, a credentials endpoint:

```http
POST /.idp/credentials HTTP/1.1
Content-Type: application/json

{
  "name": "alice",
  "email": "alice@example.com",
  "password": "password123"
}
```

Response includes authentication details:

```json
{
  "webId": "https://example.com/alice/#me",
  "podUrl": "https://example.com/alice/",
  "oidcIssuer": "https://example.com",
  "username": "alice",
  "password": "password123"
}
```

## Username Validation

- Lowercase alphanumeric and hyphens
- 3-32 characters
- Cannot start/end with hyphen
- Reserved names: admin, root, api, etc.

## Password Requirements

- Minimum 8 characters
- Stored with bcrypt (cost factor 10+)
