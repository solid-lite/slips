SLIP-22
=======

Identity Linking
----------------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | Planned |

This SLIP defines how to link WebID and did:nostr identities.

## Overview

Users may have multiple identities across different systems. Identity linking allows declaring that different identifiers refer to the same person, enabling interoperability between WebID-based Solid and Nostr ecosystems.

## owl:sameAs Linking

The standard way to link identities is `owl:sameAs`:

```turtle
@prefix owl: <http://www.w3.org/2002/07/owl#>.

<https://alice.example/#me>
    owl:sameAs <did:nostr:f0af1228a863772c0661ca0dd2586c58668de52ca9f71973404e7b9b1f5edc4d>.
```

This declares that the WebID and did:nostr refer to the same entity.

## Profile Example

Complete profile with linked identity:

```turtle
@prefix foaf: <http://xmlns.com/foaf/0.1/>.
@prefix owl: <http://www.w3.org/2002/07/owl#>.
@prefix solid: <http://www.w3.org/ns/solid/terms#>.

<#me>
    a foaf:Person;
    foaf:name "Alice";
    owl:sameAs <did:nostr:f0af1228a863772c0661ca0dd2586c58668de52ca9f71973404e7b9b1f5edc4d>;
    solid:oidcIssuer <https://login.example.com>;
    solid:publicTypeIndex </settings/publicTypeIndex>.
```

## Bidirectional Linking

For stronger verification, link from both identities.

### From WebID:

```turtle
<#me> owl:sameAs <did:nostr:f0af1228...>.
```

### From Nostr Profile (kind 0):

```json
{
  "kind": 0,
  "content": "{\"webid\": \"https://alice.example/#me\"}"
}
```

## Verification

Servers MAY verify identity links by:

1. Checking the WebID contains `owl:sameAs` to the did:nostr
2. Checking Nostr profile (kind 0) references the WebID
3. Verifying the user can sign with both keys

## Use Cases

### Single Sign-On

User authenticates with Nostr key, server:
1. Extracts did:nostr from signature
2. Resolves WebID from sameAs link
3. Grants access based on WebID ACLs

### Profile Federation

- WebID profile displayed on Nostr clients
- Nostr metadata synced to Solid profile
- Followers/contacts shared across systems

### Cross-System ACLs

```turtle
<#rule>
    a acl:Authorization;
    acl:agent <https://alice.example/#me>;
    acl:accessTo </resource>;
    acl:mode acl:Read.
```

User authenticates with did:nostr → linked to WebID → ACL grants access.

## ActivityPub Integration

For Fediverse federation, include `alsoKnownAs`:

```json
{
  "@context": "https://www.w3.org/ns/activitystreams",
  "id": "https://alice.example/#me",
  "type": "Person",
  "alsoKnownAs": [
    "did:nostr:f0af1228a863772c0661ca0dd2586c58668de52ca9f71973404e7b9b1f5edc4d"
  ]
}
```
