SLIP-47
=======

LDP Inbox
---------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes |

This SLIP defines LDP Inbox for receiving notifications and messages.

## Overview

The Inbox is a container where others can POST messages to a user. It's used for notifications, activity delivery, and inter-pod communication. The inbox concept comes from Linked Data Notifications (LDN) and is also used by ActivityPub.

## Discovery

The inbox is discovered from the WebID profile:

```turtle
@prefix ldp: <http://www.w3.org/ns/ldp#>.

<#me>
    ldp:inbox </inbox/>.
```

Or via Link header:

```http
GET /alice/ HTTP/1.1

HTTP/1.1 200 OK
Link: </alice/inbox/>; rel="http://www.w3.org/ns/ldp#inbox"
```

## Sending Notifications

Anyone can POST to the inbox:

```http
POST /alice/inbox/ HTTP/1.1
Host: example.com
Content-Type: application/ld+json

{
  "@context": "https://www.w3.org/ns/activitystreams",
  "type": "Announce",
  "actor": "https://bob.example/#me",
  "object": "https://bob.example/posts/1"
}
```

Response:

```http
HTTP/1.1 201 Created
Location: /alice/inbox/notification-123
```

## Reading Notifications

Owner reads their inbox:

```http
GET /alice/inbox/ HTTP/1.1
Authorization: DPoP ...
Accept: text/turtle
```

```turtle
@prefix ldp: <http://www.w3.org/ns/ldp#>.

<>
    a ldp:Container, ldp:BasicContainer;
    ldp:contains
        <notification-123>,
        <notification-124>,
        <notification-125>.
```

## Notification Types

Common notification types (Activity Streams):

| Type | Description |
|------|-------------|
| `Create` | New content created |
| `Update` | Content modified |
| `Delete` | Content removed |
| `Follow` | Follow request |
| `Like` | Content liked |
| `Announce` | Content shared |

## Access Control

Typical ACL for inbox:

```turtle
@prefix acl: <http://www.w3.org/ns/auth/acl#>.

<#owner>
    a acl:Authorization;
    acl:agent <https://alice.example/#me>;
    acl:accessTo </inbox/>;
    acl:default </inbox/>;
    acl:mode acl:Read, acl:Write, acl:Control.

<#public>
    a acl:Authorization;
    acl:agentClass acl:AuthenticatedAgent;
    acl:accessTo </inbox/>;
    acl:mode acl:Append.
```

This allows:
- Owner: Full access
- Authenticated users: Append only (POST)

## Pod Structure

```
/alice/
  ├── inbox/          # Incoming notifications
  │   ├── .acl        # Inbox ACL
  │   ├── msg-001.jsonld
  │   └── msg-002.jsonld
  └── outbox/         # Sent items (optional)
```

## LDN vs ActivityPub

| Feature | LDN Inbox | ActivityPub Inbox |
|---------|-----------|-------------------|
| Protocol | HTTP POST | HTTP POST |
| Format | Any RDF | Activity Streams |
| Discovery | Link header | Actor document |
| Auth | OIDC/any | HTTP Signatures |

Solid servers typically support both.
