SLIP-41
=======

Pods
----

| Status | Implemented in JSS |

This SLIP defines pod provisioning for multi-user Solid servers.

## Overview

A pod is a personal data store — a storage space where users keep their data. Pod provisioning allows servers to create new pods for users.

## Pod Structure

A typical pod contains:

```
/alice/
├── profile          # WebID profile (#me)
├── inbox/           # Messages/notifications
├── outbox/          # Sent activities
├── settings/        # Preferences
├── public/          # World-readable resources
└── private/         # Owner-only resources
```

## Provisioning Endpoint

Servers expose a provisioning endpoint at `/.pods`:

```http
POST /.pods HTTP/1.1
Content-Type: application/json

{
  "name": "alice",
  "email": "alice@example.com",
  "password": "secret123"
}
```

Response:
```http
HTTP/1.1 201 Created
Location: /alice/

{
  "webId": "https://example.com/alice/#me",
  "podUrl": "https://example.com/alice/",
  "username": "alice"
}
```

## Nostr-Based Provisioning

With SLIP-21 (did:nostr), pods can be provisioned without email/password:

```http
POST /.pods HTTP/1.1
Content-Type: application/json
Authorization: Nostr <signed-event>

{
  "name": "alice"
}
```

The pod is created with the Nostr pubkey as owner.

## Pod Discovery

The storage root is indicated in the WebID profile:

```turtle
<#me> solid:storage </> .
```
