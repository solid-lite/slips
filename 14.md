SLIP-14
=======

Conditional Requests
--------------------

`draft` `recommended` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | ✅ Yes |

This SLIP defines conditional requests using ETags for cache validation and conflict detection.

## Overview

Conditional requests allow clients to efficiently validate cached resources and prevent conflicting updates. Servers use ETags (entity tags) to identify specific versions of resources.

## ETag Generation

Servers MUST generate ETags for resources. Common approaches:

```javascript
// Content hash (recommended)
const etag = crypto.createHash('sha256').update(content).digest('hex').slice(0, 16);

// Timestamp-based
const etag = `"${stat.mtime.getTime()}-${stat.size}"`;
```

## Response Headers

```http
HTTP/1.1 200 OK
ETag: "abc123def456"
Content-Type: text/turtle
```

## If-None-Match (Caching)

Client validates cached resource:

```http
GET /alice/profile HTTP/1.1
If-None-Match: "abc123def456"
```

Server response if unchanged:

```http
HTTP/1.1 304 Not Modified
ETag: "abc123def456"
```

## If-Match (Conflict Prevention)

Client ensures update applies to known version:

```http
PUT /alice/profile HTTP/1.1
If-Match: "abc123def456"
Content-Type: text/turtle

@prefix foaf: <http://xmlns.com/foaf/0.1/>.
<#me> foaf:name "Alice Updated".
```

Server response if mismatch:

```http
HTTP/1.1 412 Precondition Failed
```

## If-Unmodified-Since

Alternative using timestamps:

```http
PUT /alice/profile HTTP/1.1
If-Unmodified-Since: Sun, 06 Nov 2024 08:49:37 GMT
```

## PATCH with Conditions

Especially important for PATCH operations:

```http
PATCH /alice/profile HTTP/1.1
If-Match: "abc123def456"
Content-Type: text/n3

@prefix solid: <http://www.w3.org/ns/solid/terms#>.
_:patch solid:inserts { <#me> <#likes> <#coffee>. }.
```

## Weak vs Strong ETags

| Type | Format | Use Case |
|------|--------|----------|
| Strong | `"abc123"` | Byte-for-byte identical |
| Weak | `W/"abc123"` | Semantically equivalent |

RDF resources may use weak ETags due to serialization variations.

## Server Requirements

Servers MUST:
- Generate ETag header for all resources
- Support If-None-Match for GET/HEAD
- Return 304 when resource unchanged

Servers SHOULD:
- Support If-Match for PUT/PATCH/DELETE
- Return 412 on precondition failure
