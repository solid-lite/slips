SLIP-51
=======

WebFinger
---------

`draft` `optional` `author:melvincarvalho`

| Status | Implemented in JSS |
|--------|-------------------|
| Draft  | Planned |

This SLIP defines WebFinger for user discovery.

## Overview

WebFinger enables discovering a user's profile and services from their email-like address (e.g., `alice@example.com`). This is required for ActivityPub federation.

## Endpoint

```http
GET /.well-known/webfinger?resource=acct:alice@example.com HTTP/1.1
Host: example.com
Accept: application/jrd+json
```

## Response

```json
{
  "subject": "acct:alice@example.com",
  "aliases": [
    "https://example.com/alice",
    "https://example.com/alice/"
  ],
  "links": [
    {
      "rel": "self",
      "type": "application/activity+json",
      "href": "https://example.com/alice"
    },
    {
      "rel": "http://webfinger.net/rel/profile-page",
      "type": "text/html",
      "href": "https://example.com/alice"
    },
    {
      "rel": "http://www.w3.org/ns/solid/terms#storage",
      "href": "https://example.com/alice/"
    }
  ]
}
```

## Link Relations

| rel | Description |
|-----|-------------|
| `self` | ActivityPub Actor document |
| `profile-page` | Human-readable profile |
| `storage` | Solid storage root |

## Resource Types

WebFinger supports multiple resource URI schemes:

| Scheme | Example |
|--------|---------|
| `acct:` | `acct:alice@example.com` |
| `https:` | `https://example.com/alice` |
| `did:` | `did:nostr:f0af1228...` |

## did:nostr Discovery

```http
GET /.well-known/webfinger?resource=did:nostr:f0af1228a863772c0661ca0dd2586c58668de52ca9f71973404e7b9b1f5edc4d HTTP/1.1
```

Response:

```json
{
  "subject": "did:nostr:f0af1228a863772c0661ca0dd2586c58668de52ca9f71973404e7b9b1f5edc4d",
  "links": [
    {
      "rel": "self",
      "type": "application/activity+json",
      "href": "https://example.com/~f0af1228/"
    }
  ]
}
```

## Server Requirements

- MUST respond to `/.well-known/webfinger`
- MUST support `resource` query parameter
- MUST return `application/jrd+json` content type
- MUST include CORS headers
- SHOULD support multiple resource schemes
